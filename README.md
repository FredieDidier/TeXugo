<h1 align="center">TeXugo</h1>
<p align="center"><i>Bravo com os erros, manso com você.</i></p>
<p align="center"><b>Português</b> · <a href="README.en.md">English</a></p>

TeXugo é um editor LaTeX local para Mac. Os arquivos ficam no seu disco, a compilação usa o seu TeX Live e nada vai para a nuvem. Serve para artigos, projetos de pesquisa, respostas aos pareceristas, pareceres, slides em Beamer, ementas, provas, listas de exercícios, relatórios e cartas. Também abre arquivos Markdown, com visualização ao lado.

## O que ele faz melhor

- **Várias abas, cada uma com o seu botão Compilar.** A aba mostra o documento raiz a que o arquivo pertence. Quando o arquivo entra em mais de um documento (por exemplo, `sections/body.tex` em `paper.tex` e em `paper_wp.tex`), um seletor deixa você escolher qual compilar.
- **Compilar tudo.** O botão do topo (⌘⇧↵) compila todos os documentos das abas abertas, cada um uma vez só, e diz quantos são ("Compilar os 2 documentos"). Passando o mouse, um balão lista quais documentos e que abas entram em cada um.
- **Zero `??` com `\externaldocument`.** Quando o paper importa os rótulos do apêndice (`xr`/`xr-hyper`) e o apêndice importa os do paper, compilar um arquivo sozinho deixa `??` no PDF. O TeXugo compila o grupo inteiro na ordem certa e repete até os rótulos se estabilizarem. Ele também sobrevive a `.aux` apagados e a `.bbl` órfãos, que fazem o `latexmk` rodar o BibTeX antes do LaTeX.
- **Cada `??` vem com o motivo.** O painel Problemas lista as referências e citações indefinidas e diz a causa provável: rótulo inexistente, rótulo que está noutro documento sem `\externaldocument`, chave que não existe em nenhum `.bib`. Os erros do LaTeX vêm com uma dica em português e a linha certa.
- **Linha do tempo da compilação.** Mostra o que está rodando, em que passada e por quê ("rótulos de paper.tex mudaram").
- **PDF ao lado, uma aba por documento.** O PDF recarrega no mesmo ponto depois de compilar. SyncTeX: ⌘J leva do código ao PDF, e um clique duplo no PDF leva à linha do código. Há um modo escuro só para a tela. Num PDF compilado fora do TeXugo, sem SyncTeX, o app explica o motivo e oferece compilar.
- **Editor de verdade.** CodeMirror com destaque de LaTeX, autocompletar de `\ref`/`\cref` (a partir dos rótulos do projeto), de `\cite` (a partir das chaves do `.bib`) e de ambientes, snippets de figura, tabela e slide, `\end{…}` automático, ⌘B/⌘I e comentário com ⌘/.
- **SyncTeX também para PDF compilado fora do TeXugo**: sem o `.synctex.gz` (PDF do Overleaf, do terminal, de outro editor), o clique duplo no PDF e o ⌘J vão pelo texto: o TeXugo procura as palavras do trecho no código e as da linha no PDF. A posição é aproximada; compilar pelo TeXugo deixa exata.
- **Git sem mensagem obrigatória**: deixe a mensagem vazia e o TeXugo escreve uma a partir dos arquivos ("Atualiza paper.tex e refs.bib"). **Sincronizar** faz commit do que mudou, pull e push num clique.
- **Atalhos e comandos** (⌘?, menu Ajuda, paleta ou tela inicial): todos os atalhos com o que fazem e onde mais achar cada comando (menu, botão, ícone), com busca.
- **Arquivos mudados fora do app** (git pull, Claude Code, outro editor) recarregam sozinhos. Se você tiver alterações não salvas, o app pergunta antes de sobrescrever.
- **Git e GitHub.** Status, diff, commit, pull e push no painel lateral, usando o git do sistema e as credenciais que o GitHub Desktop já configurou. Ao abrir um repositório, o TeXugo completa o `.gitignore` com os auxiliares do LaTeX (`.aux`, `.log`, `.fls`…), para eles não aparecerem nos commits.
- **Slides:** botão "Apresentar" para Beamer (tela cheia, um slide por vez, setas e clique) e um modo em que o PDF acompanha o cursor do editor.
- **Submissão:** ZIP que compila sozinho. Leva o `.bbl` no lugar do `.bib`, como o arXiv pede; traz para dentro os arquivos de fora da pasta do documento (como `../analysis/figuras`), com os caminhos ajustados só nas cópias; e, antes de dizer que está pronto, extrai o ZIP numa pasta vazia e compila como o arXiv faz, apontando erro, `??`, arquivo faltando ou arquivo lido de fora. **Checar antes de submeter**: anonimato para double-blind (nomes, e-mails, `\thanks`, agradecimentos, links do GitHub/OSF, caminhos absolutos com o seu usuário, comentários com nome, metadado de autor do PDF) e fontes do PDF (Type 3 e fontes não embutidas, que muitas revistas recusam); revisão de estilo com ChkTeX; contagem de palavras com texcount.
- **Pacote de replicação** (aba Revisão, aba Replicação do painel inferior ou paleta): o checklist que o Data Editor da revista vai rodar, antes que ele rode. É um só, no padrão que AEA, Econometric Society, ReStud, EJ, JEEA, JPE e outras seguem (o Data and Code Availability Standard, DCAS), e a revista escolhida muda onde o pacote vai (openICPSR, Zenodo, Dataverse, Mendeley Data), quando e alguns detalhes (README em PDF, cópia aberta de `.dta`). O TeXugo lê a pasta do projeto e confere: README na raiz e as seções do modelo dos Data Editors (e se ainda tem TODO), licença, código por linguagem, um script que roda tudo, caminhos absolutos no código, números sorteados sem seed (R, Stata, Python, Julia, MATLAB), versões dos pacotes registradas (renv, requirements, pasta ado), dados e formatos, bases de dados citadas no `.bib`, tamanho do pacote, arquivos de sistema e, para cada tabela e figura do paper, qual script a escreve. Cada aviso mostra os lugares (arquivo:linha) e abre no clique. O que só os autores sabem (direitos sobre os dados, rodar do zero numa pasta limpa, números do texto saindo do código, comitê de ética, pré-registro) vira caixa de Feito/Não se aplica, guardada em `.texugo/replication.json`. **Rascunho do README**: no formato do modelo dos Data Editors, em inglês, já com a lista de bases, os pacotes usados, a versão do R ou do Python, a linha da seed, a faixa de tamanho, os programas e a tabela "tabela/figura → programa", e TODO no que falta; nunca escreve por cima de um README (salva como `README-rascunho.md`).
- **Aba Revisão** (prancheta na barra da esquerda, com o número de pontos em aberto): tudo da revisão do documento aberto num lugar, na ordem em que acontece. *Coautores*: comentários no texto, anotações do PDF, comparar com outra versão, versões enviadas, novidades desde a sua última visita e quem escreveu cada trecho. *Pareceristas*: parecer do Claude e resposta aos pareceristas. *Antes de enviar*: vícios, referências no Crossref, checagem de anonimato e fontes, pacote de replicação, ZIP para submissão, ChkTeX e contagem de palavras. Cada linha diz em que pé está ("2 de 3 em aberto", "response.tex há 30 min") e abre a ferramenta; as listas longas ficam no painel inferior. O menu do Compilar ficou só com compilar, PDF, referência, formatação e Médico do TeX, mais um atalho para a aba.
- **Comentários no texto** (barra da seleção 💬, botão direito, ⌥⌘M): selecione um trecho e deixe um comentário para os coautores; eles respondem e resolvem. Cada conversa é um arquivo em `.texugo-comments/` na pasta do projeto e vai junto no commit, então chega a quem faz pull (um arquivo por conversa: dois coautores comentando ao mesmo tempo não dão conflito). O trecho fica marcado no editor; passe o mouse para ver a conversa. Ele é achado de novo pelo texto, não pela linha: sobrevive a linhas novas acima, à quebra de linha refeita e às suas edições no próprio trecho (o comentário acompanha o texto novo ao salvar). Se um coautor reescrever o trecho, a conversa continua na aba **Comentários** do painel inferior marcada "trecho mudou", com o texto como era. A aba Revisão conta os comentários em aberto.
- **Novidades desde a sua última visita** (aba Revisão, aba **Novidades** do painel inferior, paleta): ao abrir o projeto, o TeXugo pergunta ao remoto o que chegou e avisa quem mudou o quê desde a última vez que você olhou: por coautor, os commits, os arquivos (+/− linhas) e as **seções** que cada um mexeu (Introdução, Dados…), com clique para ir à seção, ver o diff do arquivo ou o commit. Os seus commits ficam de fora; o que está no remoto e ainda não foi baixado aparece à parte, com o botão do pull, o diff de cada arquivo e **Ver no PDF**: o paper compilado com o que chegou marcado (azul entrou, vermelho riscado saiu), antes de baixar e sem mudar nada aqui. O mesmo botão, no topo, mostra no PDF tudo o que mudou desde a sua visita. A marca da visita fica em `.git/texugo-visit.json` (de cada clone, nunca vai para o commit) e só anda quando você abre as novidades; dá para ver também os últimos 7 ou 30 dias.
- **Quem escreveu cada trecho** (ícone de pessoas acima do editor, aba Revisão, paleta): as iniciais de quem mudou cada linha por último, numa cor por coautor, pelo `git blame` do texto do editor (acompanha o que você digita antes de salvar; linhas novas aparecem como suas). Passe o mouse para ver o nome, a data e o commit; clique para ver o commit. A aba Revisão mostra quanto do arquivo é de cada um.
- **Revisar como parecerista** (aba Revisão): o seu Claude Code lê o paper inteiro, com os `\input`, e escreve um parecer no padrão do periódico que você indicar (com foco opcional): resumo, recomendação e cada comentário (principal, menor, redação) com sugestão. Cada ponto cita o trecho, e o TeXugo acha esse trecho no texto: o clique leva à linha certa. Roda em segundo plano, aparece na aba **Parecer** do painel inferior, com caixa de “resolvido”, botão que leva o ponto ao painel Claude e **Salvar .md**. Usa o modelo e o esforço escolhidos no painel Claude e só lê arquivos.
- **Resposta aos pareceristas** (aba Revisão): cole a carta do editor e os pareceres e escolha a versão submetida (um commit do Git ou o arquivo/ZIP enviado). O TeXugo calcula o que mudou desde então e o seu Claude Code separa cada comentário, rascunha a resposta e diz onde o paper mudou. Sai um `response.tex` no formato do modelo: cada comentário num quadro, a resposta, *Change in the paper* com a seção e a página do PDF (pelo SyncTeX) e *To do* em vermelho para o que ainda falta (inclusive números que não foram reestimados). Cada mudança leva um comentário `% arquivo.tex:linha`; **⌘-clique** nele (ou em qualquer `arquivo.tex:123` no editor) abre a linha. Sem revisão ainda, o Claude rascunha as respostas e o que mudar.
- **Anotações do PDF** (aba Revisão): destaques, sublinhados, tachados e notas feitos no Preview, no Acrobat ou em qualquer leitor, no PDF do documento ou num PDF que o coautor devolveu anotado (*De um PDF anotado que recebi…*). Aparecem na aba **Anotações** do painel inferior com o trecho marcado, o comentário e o autor, e cada uma ligada à linha do `.tex` (pelo SyncTeX; notas na margem e PDFs sem SyncTeX, pelo texto). Clique para ir à linha, marque como resolvida, ou mande ao painel Claude para fazer a mudança. Avisa se o PDF anotado tem outro número de páginas que o compilado.
- **Trocar o trecho marcado**: no balão de um vício, *Trocar com o Claude* reescreve só as palavras sublinhadas da frase (também no menu do Claude e na barra da seleção); você aceita ou descarta o diff.
- **Versões enviadas** (aba Revisão, aba Sugestões do painel inferior ou paleta): para quando o mesmo paper vai para várias pessoas e o retorno chega fora de ordem. Ao mandar, *Marcar o envio* guarda o texto como está, com o PDF e o SyncTeX (em `.texugo/sent`, fora do Git). Quando o retorno chega (um `.tex`, um ZIP do Overleaf, uma pasta ou um PDF anotado), ele é lido contra a versão **enviada**, não contra a de hoje: aparecem só as mudanças de quem mandou, mesmo que você já tenha incorporado as de outro coautor. Cada sugestão é comparada, palavra por palavra (quebra de linha não conta), com o que mudou desde o envio: *aplica direto* (um clique, no editor, ⌘Z desfaz; ou todas de uma vez), *já está no texto* (alguém fez a mesma correção), *conflito* (o trecho também mudou: o de hoje e a sugestão lado a lado, com *Usar a sugestão*, *Ficar com a de hoje* ou *Juntar com o Claude*) e *trecho sumiu*. Sem versão marcada, o TeXugo adivinha a base: a versão enviada ou o commit mais parecido com o que voltou. Num PDF anotado, cada nota é ligada pelo SyncTeX da versão enviada e achada na linha de hoje do mesmo trecho, com aviso quando o trecho mudou desde o envio. No fim, *Commit…* propõe a mensagem "Sugestões de Fulano".
- **Comparar com outra versão** (aba Revisão ou paleta): escolha o `.tex`, o ZIP (exportado do Overleaf) ou a pasta que o coautor mandou, ou um commit do Git, e o TeXugo gera com o `latexdiff` o PDF com as mudanças marcadas (novo sublinhado em azul, apagado riscado em vermelho), compilado com as suas figuras, tabelas e `.bib`, e abre numa aba ao lado. Compara o documento inteiro, `\input` incluídos; arquivos que a versão recebida não traz (tabelas geradas, figuras, seções que ninguém mexeu) contam como iguais aos seus. Diz quantos trechos mudaram e em quais arquivos; o PDF fica em `.texugo/diff` (fora do Git) e um botão salva uma cópia ao lado do documento para mandar ao coautor.
- **Aba Referências** (ícone do livro na barra da esquerda): todas as entradas dos `.bib` do projeto, com busca por autor, título, ano ou chave, quantas vezes cada uma é citada (e filtro das não citadas), clique para detalhes e links (DOI, arXiv, Scholar, linha no `.bib`), duplo clique ou *Citar no cursor* para citar, e **+** para adicionar.
- **Importar do Zotero** (seta para baixo na aba Referências, ou paleta): busca na sua biblioteca, marque os itens e eles entram no `.bib` (o que já está lá, pelo DOI, aparece apagado). Lê pela API local do Zotero 7 quando ela está ligada e, senão, por uma cópia do `zotero.sqlite`, sem configurar nada e sem tocar no original. **Importar .bib…** junta um `.bib` exportado do Zotero, Better BibTeX, Mendeley ou Paperpile, pulando entradas com a mesma chave, DOI ou título.
- **Biblioteca de papers** (⌥⌘B, menu Visualizar ou paleta): os PDFs que você lê, guardados uma vez para todos os projetos. Adicione PDFs, arraste-os para a janela ou traga os PDFs anexados no Zotero, com título, autores e ano de lá. O texto de cada um é lido uma vez, e a busca passa por todos: sem diferença de maiúscula ou acento, com as palavras na mesma página ou uma "frase exata", e cada resultado mostra a página e o trecho. Um clique abre o paper nessa página, com as palavras destacadas (↵ vai para a próxima); dá para abrir também no painel do PDF, ao lado do texto que você está escrevendo.
- **Verificar no Crossref** (✓ no topo da aba): confere cada entrada. Com DOI, lê o registro; sem DOI, busca pelo título e primeiro autor e só aceita o mesmo trabalho (se o Crossref não achar pela busca, tenta dentro do periódico do `.bib` e depois pelo OpenAlex; para `@article`, a versão publicada no periódico, nunca o working paper do NBER/SSRN com o mesmo título; ano a no máximo 2 de distância). Aponta DOI que leva a outro trabalho ou que não existe, e sugere ano, periódico, volume, número, páginas e DOI faltando; nada muda até você clicar em *Aplicar* (ou *Adicionar todos os DOIs*), e a correção mexe só naquele campo, mantendo o resto do `.bib` como você escreveu. Working papers, livros e relatórios que não estão no Crossref aparecem como não encontrados, sem alarme.
- **Adicionar referência** (⌥⌘R): cole um DOI, um link do artigo (ScienceDirect, arXiv) ou parte do título. O TeXugo busca no Crossref, no OpenAlex e no arXiv, mostra as opções, grava a entrada limpa no `.bib` do documento (chave no estilo `smith2020markets`, working paper do NBER com número) e já cita no cursor (`\citet` com natbib; dentro de um `\cite{}` aberto, só acrescenta a chave). Se o DOI já está no `.bib`, usa a chave que existe.
- **Corretor gramatical** em português e inglês, com o [LanguageTool](https://languagetool.org) rodando no seu Mac: ortografia sublinhada em vermelho, gramática e estilo em azul. Passando o mouse, aparecem a explicação e as sugestões, e um clique troca a palavra. O LaTeX não atrapalha: comandos, fórmulas, `\cite` e `\ref` são lidos como parte da frase, sem virar erro, e notas de rodapé são corrigidas à parte. O padrão é o modo **rigoroso**, que aponta o máximo possível: liga as regras de gramática que o LanguageTool deixa desligadas e soma uma regra do TeXugo para concordância verbal em português ("As crianças brinca no quintal" → "brincam"), que o LanguageTool não pega. Dá para trocar para o modo normal, adicionar palavras ao seu dicionário e calar uma regra em Preferências. Se o LanguageTool não estiver instalado, o item "corretor: instalar" na barra de status instala pelo Homebrew com um clique. Há também a opção de usar o servidor online do LanguageTool, que envia o texto para fora.
- **Prévia ao vivo**: com a chave "ao vivo" ligada (ao lado de Compilar), o PDF acompanha o que você digita, sem salvar. Depois de uma pausa curta, o TeXugo compila o texto que está na tela numa pasta à parte (`.texugo/live`), com uma passada só do motor, e troca o PDF sem perder a posição. Os seus arquivos e o PDF de verdade não mudam. Enquanto um comando está pela metade (uma chave sem fechar, por exemplo), o PDF fica na última versão boa e a chave mostra o erro. Como o BibTeX não roda ao vivo, citações e rótulos novos aparecem quando você compilar. O ⌘J e o clique duplo funcionam também no PDF ao vivo.
- **Prévia de equações**: com o cursor dentro de uma fórmula (`$…$`, `\(…\)`, `\[…\]`, `$$…$$`, `equation`, `align`, `gather`, `multline`…), a equação aparece desenhada logo acima, enquanto você digita, sem compilar. Usa as macros do próprio projeto (`\newcommand`, `\DeclareMathOperator`, `\def`, inclusive de arquivos `.sty`); erro de sintaxe aparece em vermelho no lugar da fórmula. Desliga em Preferências.
- **Cartão da citação**: passe o mouse sobre uma chave dentro de `\cite{}` e veja título, autores, ano e periódico, com links para o DOI, o arXiv, o Google Scholar e a entrada no `.bib`. Chave que não existe aparece em vermelho no cartão, com atalho para adicioná-la.
- **Colar tabela**: células copiadas do Excel, Numbers ou Google Sheets viram uma tabela `booktabs` ao colar num `.tex` (colunas de números centralizadas, `***` em sobrescrito, `_`, `%`, `$` e `&` escapados). Dentro de um `tabular` já aberto, entram só as linhas. Para CSV, use a paleta: *Colar tabela (Excel, CSV) como LaTeX*.
- **Formatar documento** (⌥⇧F) com o `latexindent` do TeX Live, numa edição só que o ⌘Z desfaz. Funciona mesmo no MacTeX, cujo `latexindent` costuma quebrar por falta do módulo Perl `File::HomeDir`: o TeXugo traz um substituto mínimo. Um `localSettings.yaml` na pasta do documento tem prioridade.
- **Médico do TeX:** mostra o estado da instalação e, quando a compilação reclama de um `.sty` ou `.cls` que falta, descobre o pacote do TeX Live que tem o arquivo e o instala com um clique. A senha de administrador é digitada na janela do próprio macOS. Se o TeX Live for de um ano anterior (congelado), usa o arquivo final daquele ano, o único que ainda aceita instalações.
- **Markdown** abre renderizado como no GitHub (Visualizar / Lado a lado / Código).
- **Detector de vícios de escrita** (tiques de IA), em português e inglês, sem IA e sem internet. Sublinha em roxo o vocabulário que os modelos usam muito mais que pessoas (com a época de cada palavra: *delve* em 2023–24, *showcasing* e *enhance* com o GPT‑5, *quietly* e *load-bearing* em 2025–26), travessões, “não só X, mas também Y”, gerúndio comentando a frase, “vale ressaltar que”, conclusões anunciadas, restos de conversa com o chatbot, Markdown colado no LaTeX, decalques (“the present study”, “endereçar o problema”), vírgula antes do “e” e Títulos Com Maiúsculas em português, e frases longas e encadeadas. Passando o mouse, diz o motivo, o que fazer e a fonte. Ignora o que não é texto: comentários, matemática, `\cite`, `\label`, preâmbulo, tabelas. O relatório (clique no contador da barra de status) cobre o documento inteiro, com mediana e percentis do tamanho das frases. As regras e as fontes ficam em `web/src/vicios/rules.js`, com a data da lista; são candidatos a revisar, não prova de autoria.
- **Reescrever com IA, usando o seu Claude Code.** Selecione um trecho e clique com o botão direito: Trocar o trecho marcado, Revisar, Reescrever (mais livre: muda a estrutura das frases, mantém o conteúdo), Polir (palavras melhores, mesma estrutura e tamanho), Humanizar (tirar tiques de IA, usando os vícios sublinhados como pista), Encurtar, Traduzir para o inglês, Fluidez e coesão, Deixar mais formal. O TeXugo chama o `claude` instalado no seu Mac, na pasta do projeto, com a sua conta e as suas skills (como a de escrita), e só com permissão de ler arquivos e carregar skills: ele nunca edita nada sozinho. A resposta aparece como diferença palavra a palavra, com uma nota do que mudou; Aceitar troca o trecho numa edição só (⌘Z desfaz). Um `estilo.md` na pasta do projeto tem prioridade sobre tudo; sem ele, vale um guia de estilo padrão.
- **Modelo e esforço do Claude.** No painel Claude, dois menus escolhem o modelo (Opus 5.5, Sonnet 5.5, Fable 5.1, Haiku 5.5) e o esforço (baixo, médio, alto, extra, máximo); o padrão é Opus 5.5 com esforço médio. A escolha vale para o painel, para o Claude Code no terminal e para as ações de IA na seleção. Trocar no meio de uma conversa continua a mesma conversa. Se o seu Claude Code for antigo demais para o modelo, o painel diz para rodar `claude update`. Mods do Claude Code que você tenha instalado, como o `jev-model-router` (que escolhe o esforço de cada mensagem), aparecem no painel: a linha de status do mod fica acima da caixa de mensagem e cada decisão aparece na conversa.
- **Terminal e Claude Code dentro do TeXugo.** Painel inferior, aba Terminal (⌃`): terminais de verdade na pasta do projeto, vários ao mesmo tempo, que continuam rodando se a janela recarregar. O botão **Claude Code** abre o seu `claude` ligado ao TeXugo pelo mesmo protocolo que o VS Code usa: o Claude vê a seleção em tempo real, as abas abertas e, como diagnósticos, os erros de compilação e os `??` da última compilação; cada edição que ele propõe aparece no TeXugo como diferença palavra a palavra para Aceitar ou Recusar, e ao aceitar ele grava e a aba recarrega (⌘Z desfaz). Arquivo com alterações não salvas não é sobrescrito: o TeXugo recusa e avisa. Botão direito → **Mencionar no Claude Code** põe o arquivo e as linhas no prompt. Compilar não tira você do terminal. Na primeira vez, o Claude Code pede para você entrar na sua conta.
- **Editor dividido** (⌘⌥\\ ou o botão de colunas na barra do documento): outro arquivo ao lado, como o artigo e o apêndice, ou dois trechos do mesmo arquivo. O que se digita de um lado aparece no outro na hora; ⌘S, ⌘↵ e ⌘J funcionam nos dois.
- **PDF numa janela separada**, para outro monitor, com SyncTeX entre as janelas.
- **Clonar do GitHub** direto como projeto novo.

## Rodar

Precisa do [MacTeX](https://tug.org/mactex/) (ou outro TeX Live com `latexmk`) e do Node 20 ou mais novo.

```bash
npm install
npm start
```

Para desenvolver no navegador, sem o Electron (usa preferências próprias, separadas das do app instalado):

```bash
npm run serve
```

Para gerar o `out/TeXugo.app` (arraste para Aplicativos; se já houver um TeXugo lá, ele é atualizado):

```bash
npm run package
```

Para que cada commit reinstale o app sozinho (em segundo plano; o macOS avisa quando terminar, e o log fica em `out/auto-install.log`):

```bash
git config core.hooksPath .githooks
```

Testes do motor de compilação e dos modelos:

```bash
npm test
```

## Como funciona

- `server/`: servidor local em Node. Cuida de arquivos, compilação (`build.js`), leitura do log (`logparse.js`), SyncTeX e git. Só aceita conexões de `127.0.0.1` com um token gerado a cada abertura do app.
- `web/`: interface (CodeMirror 6 + pdf.js), empacotada com esbuild em `dist/`.
- `server/doctor.js`: Médico do TeX e `latexindent`; `server/submission.js`: ZIP e checagem de anonimato; `server/replication.js` e `server/replication-journals.js`: checklist do pacote de replicação e o que cada revista pede; `server/templates/`: os modelos (versão em inglês em `<modelo>/en/`).
- `server/live.js` e `web/src/live.js`: prévia ao vivo; `server/grammar.js` e `web/src/grammar/`: corretor gramatical (LaTeX → texto, LanguageTool e a regra de concordância do TeXugo).
- `web/src/i18n.js`: tradução da interface para o inglês.
- `electron/`: a janela do Mac, os menus, o seletor de pastas e o "mover para o Lixo".
